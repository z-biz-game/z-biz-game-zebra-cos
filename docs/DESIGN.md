## 1. 题面模型

Life International 1962-12-17 的原题面（经 Wikipedia "Zebra puzzle" 词条核对，2026-09-28）给的是：
街上 N 间房子，每间在 M 个类别上各取一个值，**每个类别的值恰好各用一次**，问谁养鱼。
本仓把 M=N（经典规模 5×5），于是：

- 一个**真值** = `Int8Array truth[item] = 房子编号`，物品 id = `cat*N + idx`；
- 合法 ⇔ 每个类别单独看是 `[0,N)` 的一个排列（`isLegalTruth`）；
- 跨类别**没有**"一户只能住一个物品"的约束 —— 一户本来就要在每个类别上各取一值。
  这条是本盘与拉丁方的分界，也是 P2/P5 只在类别内成立的理由。写错它的代价见 §5。
- 解空间 `(N!)^N`：t1 216、t2 331,776、t3 24,883,200,000。
  这行数字决定了一切：**证唯一不可能靠枚举全部填法**，只能靠线索剪树 + 预算 + 三态出口。

方向口径：**"right" 指观察者的右手**（题面钉死），所以 `direct_left(a,b)` 与 `direct_right(a,b)` 是两条
不同的句子而不是同一句的两种读法。词汇恒等式 `direct_left(a,b) ⟺ direct_right(b,a)` 由
`tools/rule-test.mjs` 第 3 节钉住。

## 2. 词汇表：11 条，且否定式必须是补

句子类型取自 ZebraLogic（arXiv 2502.01100）：`at` `not` `same` `not_same` `direct_left` `direct_right`
`side_by_side` `not_side_by_side` `somewhere_left` `somewhere_right` `n_between`。

一条被实测抓到的写法错误：选型屏把"不相邻"写成 `|Δ| > 1`，于是**两人住同一间时这句话取假**——
它不是 `side_by_side` 的补。本仓写 `|Δ| !== 1`（`js/engine/rules.js:56`），
`node tools/rule-test.mjs` 第 3 节（补集恒等式，1353 项里的一族）就是抓它的；
`node --test test/rules.test.mjs` 里也留了一条最小样例：

```js
[{ k: 'not_side_by_side', a: 0, b: 7 }, true, '选型屏的 |Δ|>1 在这一格写假：同址应当为真']
```

`n_between` 只收 n≥1（本地约定，不是 ZebraLogic 原文）：n=0 与 `side_by_side` 是同一种关系，
两条等价线索在贪心删减里是**免费的**（删一条还剩一条），会把"逐条不可约"这个判据骗过去。

## 3. 两条通道 + 一个不肯复用代码的证人

| 通道 | 允许搜索？ | 用途 | 为什么存在 |
|---|---|---|---|
| `counter.js` | 允许（传播引导 + MRV） | 证唯一 | 剪树才数得完 (N!)^N |
| `pencil.js` | **不允许**（8 条具名规则） | 证"人做得出来" | 可解性是出货判据 |
| `witness.js` | 允许（朴素枚举，**零传播**） | 对账 | 防裁判自洽地给出错的"唯一" |

裁判的三态出口是本仓最要紧的口径：

```
outcome = unique   数完，恰好 1 个解    ⇒ 唯一性被证明
outcome = multiple 数到第 2 个就收工    ⇒ 盘不唯一，确定事实
outcome = none     数完，0 个解         ⇒ 题面自相矛盾（generator bug）
outcome = stopped  预算击穿             ⇒ 唯一性**未证明**，必须当失败处理
```

`provesUnique(res)` 是唯一的读法（它先看 `stopped`），所以"把 stopped 当 unique 用"在类型上就走不通。
`node --test test/counter.test.mjs` 里有一条专门的最坏情况扫描：预算 1..400 逐个试，
只要出现 `stopped && count===1` 的样本，就断言 `provesUnique===false`
（实测确实存在这类样本，所以这不是假想敌）。
裁判的叶子还有一次自检复核：`leafInvalid` 必须恒为 0 —— 传播若删漏约束，这里会给出一个不满足题面的"解"。

`witness.js` 故意不复用 `counter.js` 的任何东西（没有掩码域、没有支撑表、没有弧一致性、没有 MRV），
两条通道只共享 `rules.js` 的 `evalClue`。它慢一到两个数量级，所以只用于抽样复核：
`SAMPLES=60 node tools/balance.mjs` 每档抽 8 张，本跑 `{"agree-unique":8}` × 3 档。
见证被掐断时 balance 打的是"复核未成"（inconclusive），**不当 pass 也不当分歧**。

## 4. 铅笔：P1–P8，每次删除只记到一条规则名下

```
P1 点名消元（at / not）           P5 房位容量（某类某房只剩一个够得着的物品）
P2 同类互斥（类别内 all-different） P6 显性数组（k 个物品只占 k 间 ⇒ 承包）
P3 锚定转移（二元线索一端已定）     P7 隐性数组（k 间只有 k 个物品够得着 ⇒ 锁死）
P4 关系弧一致（两端未定的支撑过滤）  P8 跨类占位检验（假设 + 逐类别匹配支撑，假设不落盘）
```

P8 是唯一的"类猜测"，但它猜的是**存在性**而不是赋值：假设"A 住第 h 间"后逐类别做二分图匹配
（`hasSDR`，Kuhn 增广），配不上才删 h。它被**推迟到弱规则不再变化的那一轮**才跑，
所以每张盘的 P8 出场数是一个读数，不是噪声。

实测出场（删除位数，`SAMPLES=60 node tools/balance.mjs`）：

| 档 | P1 | P2 | P3 | P4 | P5 | P6 | P7 | P8 |
|---|---|---|---|---|---|---|---|---|
| t1 | 105 | 387 | 260 | 192 | 93 | 0 | 0 | 43 |
| t2 | 235 | 944 | 665 | 682 | 251 | 61 | 0 | 42 |
| t3 | 450 | 1853 | 1344 | 1636 | 461 | 181 | 0 | 75 |

P7 在 FULL 里恒为 0 —— 这是**被解释得通的**：P7（隐性数组）能删的值，P5+P6 的组合已经先删掉了。
`node tools/pencil-test.mjs` 第 1 节因此用 `BASIC + 只加 P7` 给它找证人（实跑得 2 次出场），
而不是让一条规则挂着 0 出场混进"看起来有用"的名单。

同一批 75 张出货盘上（`node tools/pencil-test.mjs`）：**FULL 推完 75/75，BASIC(P1..P5) 只推完 66/75**
—— 差的那 9 张就是 P6/P7/P8 买到的东西。而在 balance 的成品盘上（`SAMPLES=60`）
BASIC 能推完 52/60、50/60、46/60（87% / 83% / 77%）：**这就是"出货靠选择、不靠运气"的读数** ——
出货盘 100% 被 FULL 推完，但其中相当一部分用基础规则就够，这正是人题的手感来源。

铅笔的两条性质分得很清：

- **soundness（错才是红）**：`auditAgainst` 逐条比对定值结论与真值（0 冲突），
  以及对全部解的 ⋂解审计（`pencil-test` 第 3 节，可比 179 张）；
  第 6 节的负对照 planted 一个"猜"出来的定值，被抓 75/75。
- **弱不是错**：推不完只是不出货，不许假装推完。第 5 节（能力上界）断言任何规则都不许删掉
  "出现在某个解里"的值 —— 可比 104 张，0 例越界；单独跑 P8 在 75 张盘上删 1083 位也全部合规。

## 5. 一条把门禁打红的真 bug：P8 删多了

P8 最初把"假设 A 住第 h 间"实现成"从**所有**类别的别的物品里挖掉 h"，于是 102 个可满足 CSP 被判成矛盾。
错在哪：**一户本来就要在每个类别上各取一值**（§1），别的类别照样有人住 h。修正后只挖 A **自己类别**：

```js
for (const x of cats[catOf(v, N)]) if (x !== v && (probe[x] & (1 << h))) probe[x] &= ~(1 << h);
```

这条的方向值得记：**这类 bug 的表现是"过强"而不是"过弱"** —— 它不会让盘出货不了，
它会把好盘全毙掉，并且看起来像"这一档养不出货"。所以 `pencil-test` 第 2/3/5 节必须同时存在。

## 6. 出题流水线与那根被修正的偏差

```
1) 抽真值：每类独立抽排列
2) 建候选池：按档位权重 MIX 加权抽，**每一对物品最多一句话**，at 只有配额条（不是 N² 全量锚点）
3) 贪心删线索：`zebra|<tier>|<seed>|shrink` 的随机序，删完仍被裁判**证明**唯一才删
4) 铅笔验收：空盘跑 FULL，推不完 ⇒ 整张丢弃重抽
```

两个设计判断都直接对着选型屏（`_tmp-zebra-screen.mjs`，2026-09-28 重跑读数）的偏差来：

**a) 构成偏差。**屏上 5×5 出货盘平均带 4.0 条 `somewhere_left` + 3.4 条 `side_by_side` + 0.9 条 `at`
（合计 39.6%），那是"生成器能生成什么就有什么"的产物。真人题面以 `same` / `at` / 否定式为主，
所以本仓把权重写成显式 `mix`（t3：`same 26 · not 10 · not_same 18 · direct 8 · side_by_side 10 ·
somewhere 12 · not_side_by_side 8 · n_between 6`）。出货实测构成（`SAMPLES=60 node tools/balance.mjs`）：

```
same 5.9(35%) · direct 2.1(13%) · side_by_side 1.8(11%) · somewhere 1.8(11%) · at 1.8(10%) ·
n_between 1.2(7%) · not_same 1.0(6%) · not_side_by_side 0.7(4%) · not 0.5(3%)
somewhere+side_by_side 合计 21.4%（对照屏的 39.6%）· 11/11 种线索类型都在三档出现过
```

**b) 白送的"不可约唯一"。**屏的种子池永远含全部 N² 条 `at` 锚点，于是"池子能撑起唯一解"是被结构保证的，
它报的 200/200 不可约唯一没有信息量。本仓把 `at` 压成配额（t1/t2/t3 各 2/3/4 条）后，
这件事变成一个**测出来的拒收数**：`pool-not-unique` 实测 t1 0 次、t2 5 次、t3 30 次（各 60 张盘、
分别用 79 / 138 / 186 次抽取，`SAMPLES=60 node tools/balance.mjs`）。
同一条命令连跑两个进程，这三行读数逐字节相同（79/138/186 · pencil-stall 19/73/96 · pool-not-unique 0/5/30，
本机 2026-09-28）—— 这就是 §8 那条"预算不参与判定"的兑现方式。

线索数均值的横向对照：t2 = 10.2 条，与 ZebraLogic 论文读数的**均 10.4 / 中位 9** 同一量级；
t3 = 16.8 条高于它。解释（不是测量）：本仓的出货判据是"逐条不可约 **且** 空盘被 FULL 推完"的合取，
5×5 上同时满足两条的不可约集通常比 4×4 更长。我们没有为了让数字对齐而放宽任何一条红线。

## 7. band / budgetMs：只取尾巴

`TIERS[].band`（draws/盘）与 `budgetMs`（单次裁判毫秒预算）必须由 `SAMPLES=60 node tools/balance.mjs`
的分位表回填，规则写在 `tools/balance.mjs` 头部：

- 回填建议是 `band = [max(1, floor(中位×0.4)), max(lo+1, ceil(p95×1.6))]`（`tools/balance.mjs:182`），
  而红线 R4 判的只有一件事："draws/盘 的中位仍落在钉住的那条带里"（`balance.mjs:184`）——
  **不取中位×2**。本组织的出题墙钟是双峰的，中位×2 曾经盖住一根 4 倍尾巴。
  `SAMPLES=60` 的建议带是 [1,4] / [1,10] / [1,15]，钉住的是 [1,4] / [2,10] / [2,15]
  （`js/engine/generate.js` 的 `TIERS[].band`）：**下界故意比建议紧**。下界是"这一档不该退化到入门档"
  的声明，掉下去要红一次、由人显式重抄，而不是让闸自己悄悄放宽。
- budgetMs 取**生产路径上每一次裁判调用**的 p95 × 4 向上取整到 10 ms、下限 10 ms
  （`balance.mjs:183`）。注意量的是生产路径（删线索途中的题面更松、更贵），不是成品复核
  —— 只量成品会把预算定小。本跑三档生产 p95 = 0.013 / 0.009 / 0.015 ms ⇒ 建议仍是 10 ms。
- 判定只认 p95，单次 max 只作读数（墙钟在本机是上界，loadavg 印在每次跑的表头上）。
- 盘号设计成前缀稳定的（第 i 局的 base seed 就是 `b<i>`），SAMPLES 改大只会追加新盘，
  所以 60 的重抄能对账 24 的那 24 张。
- 出货序列是 seed 的**纯函数**，前提是时间预算不参与判定。这条被钉成红线 R4d：
  生产路径击穿一次 ⇒ 红（本跑 1140/1980/3060 次调用，击穿 0）。

## 8. 复现性

seed 串形状 `zebra|<tier>|<seed>`（档位写进串里，换档不会把另一档的盘重洗），
补抽写 `#d`。全仓只有一个 PRNG（splitmix32 over FNV-1a，`js/engine/rng.js`），只吃字符串。

被显式禁止的三件事：`Math.random(`、`Date.now(`、**比较器吃随机数**。
第三条的理由是 V8 的 `Array#sort` 实现与数组长度有关（长数组 TimSort、短的用插入排序），
相等元素的次序在 node 与 Chrome 之间不同 ⇒ 比较器一吃随机数，浏览器和 CI 就会挑出不同的盘。
`keyed()` 的做法是把随机键预抽成数据，排序只看 `(键, 编号)`。
`node --test test/determinism.test.mjs` 里有一条**跨进程**断言：新起一个 node 进程跑同三个 seed，
题面签名与真值签名逐字节相同（本跑通过，29/29）。

## 9. 台阶实验：为什么 band 不是线索数

把成品盘已删的线索按原路加回去，在每个台阶点量"铅笔剩余未定值"，得秩相关与"加回线索反而更难"的次数：

```
t1：140 个台阶点 / 120 次相邻步 · rho(线索数, 未定值) = −0.138 · 台阶倒退 1 次
t2：160 / 140 · rho = 0.012 · 倒退 1 次
t3：180 / 160 · rho = 0.054 · 倒退 1 次        （SAMPLES=60 node tools/balance.mjs，2026-09-28）
```

选型屏在 4×4 与 5×5 各测到 1/360 次倒退，量级一致。机制是清楚的：**P5/P6 这类存在性规则不是支撑规则**，
加一条线索可能把"某间只剩一个人够得着"里那个唯一够得着的人划掉，从而撤销整条连锁。
结论写进承诺的措辞里：难度档用 `(规模, 线索数区间)` 表述、由 draws/盘 与实测铅笔推完率钉住，
**绝不写成"线索越少越难"**。

## 10. 被否决的写法（一览）

| 否决 | 理由 |
|---|---|
| `not_side_by_side = \|Δ\|>1` | 不是肯定式的补（§2），同址时应为真 |
| P8 跨类别挖房子 | 过强的错：把可满足盘判成矛盾（§5） |
| 池子恒含 N² 条 `at` 锚点 | 让"不可约唯一"变成结构白送（§6b） |
| band = 中位×2 | 双峰墙钟下盖住尾巴（§7） |
| budgetMs 由成品复核成本定 | 成品比删线索途中的题面**便宜**，预算会定小（§7） |
| 比较器里抽随机数 | 换机器/换引擎换一批盘（§8） |
| 手工盘 / 关卡包 | 绕过全部五道闸（四道度量 + 浏览器），商品的一部分从未被证明过 |
| 把 stopped 读成 unique | §3；R2/R4d 直接红 |
| 声称"挪威人那条使原题非唯一" | 溯源 NOT FOUND 的网络讹传，不写 |
| 声称线索数是单调难度轴 | §9 自己有反例 |
| shipped 模块里写 `import … from 'node:perf_hooks'` | node 四道闸全绿、浏览器在第一条语句上死（§12） |
| 选中类别对时 `replaceChildren` 重建导航按钮 | 焦点甩回 body，且闸拿到脱离文档的幽灵节点（§14） |
| 整条 `trace` 存在 `Game` 上 | 那等于把一盘题的完整解题序列挂在 `window` 上给 BFS 扫（§13） |
| 提示的"高亮像素 > 0"挂在最后一步上 | 那一步可以合法地不给任何格子（§15） |
| 用"两间房选同一个物品"当"破一条线索" | 那是分配**不完整**，不是题面为假（§16） |
| 隐藏面板只写 `hidden` 不写 `[hidden]{display:none}` | 作者侧的 `display:grid` 盖过 UA 那条，"藏起来"的面板照样被 `elementFromPoint` 命中（§17） |

```

            has been blocked by CORS policy: Cross origin requests are only supported for …
```

读法有两层。**第一层**是浏览器给出的形态不是"解析错误"而是 CORS/`net::ERR_FAILED`
（Chrome 把 `node:` 当成一个跨源 scheme）；**第二层更要紧**：模块图整个不执行时，页面不会红着
报告任何东西 —— 症状是**沉默**。所以这条闸不能靠"场景自己断言失败"，必须靠 §17 那条
`WANT_N`（该交回几段由注册表决定），否则一次 0 断言的跑会被读成"0 failed"。
修法不是 try/catch 兜一层，是删掉那行：`performance` 在 node ≥16 与浏览器里都是全局，
同一个钟、同一个 `performance.now()` ⇒ ms 读数与换行之前同源，少一行 import 不是放宽口径。
钉住它的两条读数：`boot` 要求"启动期既没有未捕获异常也没有资源 404"（`tools/scenarios.js:241`），
以及 verify.sh 在跑任何断言之前先做一次 404 预检、把打到的 404 原样打印出来
（本轮两种形态各打了一条 `favicon.ico` —— 打印出来才算量过）。

## 13. 答案路径：`truth` 在 `makeBoard()` 里就该死掉

浏览器闸有一条不看功能只看**对象图**的断言，所以"页面上没有答案"必须是结构性的：

- `makeBoard()` 交出去的 board 只有 `{tierKey,N,label,seed,seedStr,clues,clueCount,draws}`；
  生成器的 `truth` 只在函数体内活一瞬（交给 `proveBoard` 复核用）。
- 引擎回执里那句 `truthReasons`（"生成器自己的答案满不满题面"的理由数组）在
  `js/ui/game.js:49-52` 被折成一句 `truthNote`，数组本身不出函数 —— 它是阶段一那条
  "按名字扫对象图"的断言唯一的入口。
- **整条 trace 不留在模型上**：`Game` 只存计数（`steps/rounds/fire/used`，
  `js/ui/game.js:112-120`），按提示时现算一次带 trace 的 `solve`。存下完整序列等于把这一盘
  从头到尾的解题路径挂在 `window.zebra` 上，而 `boot` 要 BFS 扫这张图（读数用 `nodes > 60`
  钉住"扫描真的覆盖了对象图"，不写死具体节点数 —— 对象图会随功能长）。
- 判分读的是**玩家填的**分配：`rules.checkSolution(N, claim, clues)`；"谁养 X"由
  `petOwner(claim)` 从玩家自己填的那组分配里读出来。唯一性来自 `proof` 的读数
  （`outcome=unique && count=1 && !stopped`），不是来自"我对了一下答案"。

## 14. 阶段二第一轮红了 15 条：哪条是产品的错，哪条是断言自己的前提错

一次跑红 15 条时最贵的事是逐条打补丁。这一族的共同点是**测量位置错了**，而"产品 vs 前提"
必须一条一条判，判错了就会把 bug 钉成期望值。表里每一行的证据都是一个可跑的读数：

| 现象 | 判定 | 一句话证据 |
|---|---|---|
| 五枚类别对按钮"零尺寸"、`aria-current` 不跟光标走 | **产品 bug** | 选中时 `renderPairs()` 无条件 `replaceChildren` ⇒ 手上那批引用脱离文档、rect 变 0×0、焦点甩回 body。改成只在类别对集合变化时重建（`js/main.js:107-124`），闸同时断"点完导航，旧引用仍在文档里且是同一枚节点"（`tools/scenarios.js:595-597`）——这一条不复现，屏幕上什么都正常 |
| 前几格 `elementFromPoint` 命中画布、`cellAt` 却解回 null | **闸的前提错** | bounding rect 是在滚动画布**之前**取的，之后才拿它去减指针坐标 ⇒ 差的正是 scrollY。改成先 `scrollIntoView` 再在同一帧取 rect（`tools/scenarios.js:199-206`、`287-301`）；命中半径仍然 `max(6, round(cell×0.4))` 且必须 ≤ 半格 |
| `seed 串` 断言少了 `#补抽序` 尾巴 | **闸的前提错** | 串的形状是 `zebra\|档位\|盘号#补抽序`（§8），同一个仓里 boot 那条按夹具比 `zebra\|t1-3cat\|b0#0` 是绿的 —— 两条断言自己互相矛盾，红的是手打字面量那条（现改为整串对 node 夹具，`tools/scenarios.js:450-455`） |
| 撤销后"与空帧逐位相同"差 528 个像素 | **闸的前提错** | 光标框画在格子**内部**（`js/render/board.js:154-156`：2px 线宽、贴内沿 ⇒ `cell=68` 时是 68²−64² = 528 个像素），所以"落子前"那一帧与"清空后"那一帧本来就不该相同。基线帧改定义为"光标在这一格、注记为空"的那一帧，**阈值仍是逐位 0 差异**，并加一条"基线帧与隔壁空格至少差 20 个像素"证明它不是全画布底纹 |
| 冲突行的第三格没被标红 | **产品 bug** | 画布只给已落子的那两格变色，等于让玩家自己猜第三格算不算嫌疑。改为冲突行/列每一格描红边、还空着的那几格加 `SUSPECT` 底纹；闸两头都断：第三格有红、没冲突的行**一点红都没有**（`tools/scenarios.js:573-578`） |

## 15. 提示不代劳：删候选位 ≠ 删得动逻辑格上的某一格

`hint` 那一段原本把"高亮像素 > 0"挂在"按了三次之后的最后一步"上。t1-3cat/b0 的第 3 步（P4）
在 node 夹具里 `cross=0、check=0`：这一步的删除是真的（候选位确实少了），但两端候选集还没交集
为空 ⇒ 逻辑格上没有任何一格可以写。所以红的是**断言挂的位置**，不是画布。现在的读法是：

- 循环里逐步对账 —— 这一步给出的每一格必须真的在画布上高亮（✗ 用红色调、✓ 用绿色调），
  同一类别对里**其余每一格**必须一点提示色都没有；
- 没有新蕴含格子的那一步，画布上必须**一笔提示色都不画**（`hintTintCount === 0`，
  顺带把上一格的残影也测了）；
- 末尾那两条总体读数只挂在"给出了格子的最后一步"上，并且额外要求三步里至少有一步给出格子
  （否则那两条没有可测对象 —— 这条本身就是防"绿灯空转"的）。

node 夹具里那三步的 `cross|check` 两列就是这条判断的证据；重算命令
`node tools/fixtures.mjs`（verify.sh 每次先跑 `--check`，本轮 `14/14 条夹具`）。

## 16. "不判"与"不满足"是两件事

`answer` 那一段想测"破一条线索 ⇒ 裁判给可核对的理由"，实现是把两间房改成选同一个物品。
但面板是**每间房选一个物品**的下拉组，`readClaim` 把房子记在物品上
（`js/main.js:194-205`），于是"两间房同一物品"必然意味着"第三个物品没人选" ⇒ 交出去的分配
**不完整**，而 judge 的口径是不完整就不猜（`js/main.js:211-215`），所以那句话给的是 `missing`
计数。原断言读的是"不满足 + reasons"，红的还是位置。现在两种破法各测各的：

- 两间房同一物品 ⇒ 断言 `complete===false && missing===1 && reasons===undefined`（不编理由）；
- 要"完整而且仍每类各用一次"的破法，得**对调两间房**。node 侧把这张盘的两两对调全枚举过：
  t1-3cat/b0 共 3 个类别 × C(3,2) = **9 个候选，破掉 9 个 / 仍成立 0 个**，第一条理由形如
  `线索 1 在真值上为假: 人:小红 和 颜色:绿房子 住同一间`（2026-09-28 实跑，
  `node --input-type=module -e …`）。所以这一族断言测的是**裁判对题面的读法**，
  不是排列合法性。

## 17. 两种 URL 形态、每腿一个新 profile、以及"少跑一段就是红"

`tools/verify.sh` 跑 root（仓库自己当文档根）与 Pages 前缀（`/<repo>/`）两种形态，各用一个
**新 mktemp 出来的 Chrome profile**：复用 profile 会带着上一形态的 localStorage，于是"跨刷新续档"
那一对断言变成自己读自己刚写的内存。前缀形态必须单跑：页级 `/js/...` 说明符在 root 形态下能被
本地服务器蒙对，挂到 `/<repo>/` 下就 404，而 dynamic import 抛错会把整段注入脚本一起带沉 ——
部署站点于是**静默地**只跑了一小部分断言。闸自己也不信"跑完了就算"：该交回几段结果由注册表决定
（`WANT_N = 注册场景数 + urlseed 三趟`，`tools/verify.sh:107`），少一段即红；每段场景的断言条数
由页面自己交回，本轮两形态各 15/15 段、413 条 checks、0 失败。

`[hidden]` 这条坑是真的：作者侧写了 `display:grid/flex` 的 section 会盖过 UA 的
`[hidden]{display:none}`，于是"藏起来"的面板照样能被 `elementFromPoint` 命中、被 `getClientRects`
量到 —— 指针闸接着去怪控件。`css/game.css` 里每一段带 display 的 section 都自带一条
`[hidden]` 规则，闸那边不看属性、看**结果**：`hiddenTight()` 要求
`el.hidden && getComputedStyle(el).display === 'none' && el.getClientRects().length === 0`
三者同时成立（`tools/scenarios.js` 的 `hiddenTight/whyNotTight`），`whyNotTight` 把三项读数原样
打印进失败信息。
